# Оценка семантической корректности TLA+ спецификаций, сгенерированных LLM

Проект выполнен в рамках варианта 1 дисциплины «Технологии верификации и тестирования программного обеспечения».

Цель эксперимента — проверить, насколько большая языковая модель способна построить TLA+ спецификацию по текстовому описанию системы, а затем определить, совпадает ли её поведение с эталонной спецификацией (*Gold*). Для проверки использовались SANY и TLC, а для семантического сравнения — проверки включения поведений в обоих направлениях и проверка свойств Gold на сгенерированных спецификациях.

## Модель и инструменты

- **Модель:** `DeepSeek-V4-Pro-0813`.
- **Идентификатор API:** `deepseek-v4-pro-0813:free`.
- **Провайдер API:** LiteRouter, OpenAI-совместимый endpoint `https://api.literouter.com/v1`.
- **Параметры генерации:** не переопределялись и не фиксировались; API не возвращал поле `model`, поэтому фактическая модель ответами не подтверждена.
- **Верификатор:** `tla2tools.jar`, SANY и TLC 2.19 (08 August 2024).
- **Java:** 21.

## Методика

Эксперимент состоит из двух этапов.

1. **Генерация и исправление спецификации.** На первом шаге модели передавались текстовое описание задачи, содержимое `.cfg`, имя модуля и требования к результату. Использовался подход zero-shot с кратким запросом рассуждать перед выводом спецификации. Примеры и экспертные подсказки не предоставлялись. Полученная спецификация проверялась SANY, затем TLC. При ошибке модели передавались текущая версия спецификации и полный лог соответствующего инструмента. Gold-спецификация на этом этапе не использовалась. Лимит — 10 итераций на задачу.
2. **Семантическая проверка.** После получения спецификации, проходящей SANY и TLC, сравнивались метрики пространства состояний Gold и генерации, проверялось включение поведений `Generated => Gold`, проверялись инварианты и temporal-свойства Gold на генерации, а затем выполнялась обратная проверка `Gold => Generated`. Отображение переменных между спецификациями задавалось вручную.

Подробный протокол и команды запуска приведены в [docs/PROTOCOL.md](docs/PROTOCOL.md). Результаты семантического анализа и интерпретация приведены в [docs/conclusions.md](docs/conclusions.md).

## Набор задач

Выбраны четыре задачи из [TLA+ Benchmark](https://github.com/LUC-AI4FM/tla_benchmark/tree/dataset-release/dataset_release): две базовые (`basic`) и две средние (`intermediate`). Для каждой задачи в `dataset/` находятся описание, конфигурация TLC, эталонная спецификация и ссылки на исходные материалы.

| Задача | Уровень | `spec_id` | Краткое описание |
|---|---|---:|---|
| `AsynchInterface` | лёгкий (`basic`) | 891 | Асинхронный интерфейс отправителя и получателя |
| `TCommit` | лёгкий (`basic`) | 1127 | Двухфазная фиксация транзакции (Two-Phase Commit) |
| `SimpleAllocator` | средний (`intermediate`) | 1000 | Распределение ресурсов между клиентами |
| `SyncTerminationDetection` | средний (`intermediate`) | 1067 | Обнаружение завершения в распределённой системе с кольцевой топологией |

## Результаты генерации

Все четыре итоговые спецификации прошли SANY и TLC с заданными `.cfg` не более чем за пять итераций.

| Задача | SANY пройден | TLC пройден | Всего итераций |
|---|---:|---:|---:|
| `AsynchInterface` | 1 | 1 | 1 |
| `TCommit` | 1 | 2 | 2 |
| `SimpleAllocator` | 2 | 5 | 5 |
| `SyncTerminationDetection` | 2 | 3 | 3 |

Прохождение этих проверок подтверждает корректность спецификаций относительно их собственных конфигураций, но само по себе не гарантирует соответствие Gold. Например, в `SimpleAllocator` модель изменила формулировку одного из свойств живости, поэтому прохождение исходного `.cfg` не выявило семантического расхождения.

## Результаты семантической проверки

Метрики указаны в порядке `Distinct States / States Generated / Max Depth`. `States Generated` — число состояний, сгенерированных TLC, а не число переходов.

| Задача | Gold | Сгенерированная | `Generated => Gold` | `Gold => Generated` |
|---|---:|---:|---|---|
| `AsynchInterface` | 12 / 30 / 2 | 12 / 27 / 4 | Выполняется | Нарушено |
| `TCommit` | 34 / 94 / 7 | 46 / 97 / 7 | Нарушено | Нарушено |
| `SimpleAllocator` | 400 / 1633 / 6 | 43 / 94 / 5 | Нарушено | Нарушено |
| `SyncTerminationDetection` | 129 / 3722 / 1 | 258 / 1860 / 2 | Выполняется | Нарушено |

Две генерации (`AsynchInterface` и `SyncTerminationDetection`) являются сужениями Gold: их поведения допустимы в Gold, но часть поведений Gold потеряна. В `TCommit` и `SimpleAllocator` прямое включение нарушено — сгенерированные спецификации допускают поведение, которого нет в Gold. Ни одна из четырёх спецификаций не эквивалентна Gold, поскольку обратное включение нарушено во всех случаях.

Подробнее о причинах расхождений — в [выводах](docs/conclusions.md).

## Воспроизведение

Требуются Python 3 и Java 21. Для генерации нужен ещё API-ключ LiteRouter, но модель `deepseek-v4-pro-0813:free` сейчас недоступна: повторить генерацию нельзя, а сохранённые данные проверяются без API (`verify_logs.py`, `compare_gold.py`). Для точного воспроизведения результатов используйте TLA+ Tools 2.19 (08 August 2024). Файл `tla2tools.jar` нужно положить в `tools/tla2tools.jar` (или в корень репозитория); исполняемые скрипты ищут архив в этих двух местах. В Git каталог `tools/` игнорируется, поэтому JAR нужно разместить локально.

```powershell
# PowerShell: подготовить настройки
Copy-Item .env.example .env
# Открыть .env и заполнить LITEROUTER_API_KEY

# Скачать TLA+ Tools 2.19 из официального списка релизов:
# https://github.com/tlaplus/tlaplus/releases
# Сохранить файл как tools/tla2tools.jar

# Сгенерировать спецификации для всех четырёх задач
python src/run_experiment.py --all

# Выполнить семантическое сравнение сохранённого прогона с Gold
python src/compare_gold.py --run runs/deepseek-v4-pro-0813_free

# Собрать сводную таблицу по сохранённым логам (API не нужен)
python src/verify_logs.py
```

Для одной задачи вместо `--all` можно передать путь к каталогу, например:

```powershell
python src/run_experiment.py dataset/easy_891_AsynchInterface
```

Повторный запуск поверх существующих результатов требует флага `--force`: прежний каталог задачи переносится в `runs/.backup/`, затем прогон начинается заново. Семантический скрипт пересоздаёт каталог `semantic/` соответствующего прогона.
