# Протокол эксперимента (вариант 1): LLM -> SANY -> TLC

Модель: `deepseek-v4-pro-0813:free` через LiteRouter (`https://api.literouter.com/v1`, OpenAI-совместимый API).
Техника промптинга: zero-shot + краткий Chain-of-Thought («think step by step briefly»), диалог многошаговый
(модель видит свои предыдущие ответы и логи).

## Запуск

```
copy .env.example .env      # вписать ключ: LITEROUTER_API_KEY=...   (.env в git не попадает)
python tools/run_experiment.py dataset/easy_891_AsynchInterface     # одна задача
python tools/run_experiment.py --all                                # все 4 задачи
```

Опции: `--model`, `--max-iter 10`, `--temperature` (по умолчанию не передаётся), `--out runs`, `--force`
(перезаписать существующий прогон; без него существующий прогон пропускается).

## Правила
- Максимум **10 итераций** на задачу. Итерация = один промпт + один ответ.
- Модели нельзя давать подсказки. Контекст: описание, `.cfg`, свой код и логи SANY/TLC.
- **Gold показывать нельзя.** Скрипт читает из папки задачи только `description.txt` и `.cfg`.
- Если не получилось за 10 итераций, нужен разбор причин (создаётся заготовка `failure_analysis.md`).

## Шаблоны промптов (`tools/prompts/`)
| Файл | Когда используется | Плейсхолдеры |
|---|---|---|
| `1_generate.md` | итерация 1 | `{DESCRIPTION}`, `{CFG_CONTENT}`, `{MODULE_NAME}` |
| `2_sany_error.md` | предыдущая итерация упала на SANY | `{CURRENT_SPEC}`, `{FULL_SANY_LOG}` |
| `3_tlc_error.md` | SANY прошёл, упал TLC | `{CURRENT_SPEC}`, `{CFG_CONTENT}`, `{FULL_TLC_LOG}` |

Логи подставляются **целиком**. При timeout TLC модели уходят последние 100 строк лога с пометкой, что лог обрезан.

## Что делает скрипт на каждой итерации
1. Отправляет промпт (итерация 1: генерация, далее: по типу последней ошибки).
2. Берёт код из ответа без правок: последний блок ```` ```tla ````, содержащий целый модуль. Сохраняет как `spec_iterN.tla`
   и как `<MODULE_NAME>.tla` в `work/`.
3. SANY: `java -cp tla2tools.jar tla2sany.SANY <MODULE_NAME>.tla > sany_N.log 2>&1`.
   (SANY возвращает код 0 даже при семантических ошибках, поэтому успех определяется по маркерам в логе:
   `Fatal errors`, `Semantic errors`, `*** Errors`, `Could not parse`, `Abort messages`.)
4. TLC (если SANY прошёл): `java -cp tla2tools.jar tlc2.TLC -config <MODULE_NAME>.cfg -workers auto <MODULE_NAME>.tla > tlc_N.log 2>&1`,
   с таймаутом 600 с.
5. Остановка, если SANY и TLC прошли, или после 10 итераций.
6. Строка в таблицу ошибок.

## Классификация ошибок
**SANY:** синтаксис, неопределённое имя, выдуманный оператор или модуль, неверный уровень выражения,
неверное число аргументов, имя модуля не совпало с файлом.

**TLC:** deadlock, нарушение инварианта, ошибка конфигурации (константа не определена, имя в `.cfg` не найдено),
нарушение temporal-свойства, ошибка вычисления (тип, пустое множество, выход за домен), timeout.

Тип определяется автоматически по тексту лога (эвристика), столбец «Что сломано» содержит первую строку ошибки.
Их **нужно просмотреть и при необходимости отредактировать руками** в `results.md`, формулировка для отчёта «одной фразой» — на вашей стороне.

Пример таблицы:

| № | SANY | TLC | Тип ошибки | Что сломано (одной фразой) |
|---|------|-----|------------|----------------------------|
| 1 | fail | – | синтаксис | не закрыт `\E`-блок |
| 2 | ok | fail | deadlock | `Next` не покрывает конечное состояние |

## Что сохраняется: `runs/<модель>/<задача>/`
| Файл | Содержимое |
|---|---|
| `run.log` | полный журнал с временем: отправка, ответ, SANY, TLC, ошибки API |
| `prompt_N.md`, `response_N.md` | отправленный промпт и полный ответ модели |
| `api_N.json` | сырой ответ API (usage, возможный reasoning) |
| `spec_iter1.tla` … `spec_iterN.tla` | все версии спецификации |
| `sany_N.log`, `tlc_N.log` | полные логи |
| `results.md`, `results.csv` | таблица итераций + метрики (SANY@, TLC@, всего итераций, финальный вывод TLC) |
| `summary.json` | то же в машиночитаемом виде (`states generated`, `distinct states`, `depth`) |
| `transcript.json` | весь диалог целиком |
| `failure_analysis.md` | заготовка разбора, только если за 10 итераций не получилось |

## Для отчёта
- Метрики берутся из `results.md` / `summary.json`.
- Для п. 4 (семантика) в `summary.json` есть `final_tlc` — числа для сравнения с Gold
  (Gold: AsynchInterface 12 / 30 / 2, TCommit 34 / 94 / 7, SimpleAllocator 400 / 1633 / 6, SyncTerminationDetection 129 / 3722 / 1
  в формате distinct / generated / depth).
